# 评测范围与人工评分

## 分类自动评测

`evals/cases.json` 固定 20 例，`run_evals.py` 将结果分为两类，不把总数当作模型语义总分：

- **独立 fixture／脚本（13 项）**：word200、阅读、编程、英文、居家、条件式拒答、换条件复用、摄影和团队通用模式均使用各自完整 JSON；另覆盖超预算、重复阶段名、无检查点、非有限时间、步骤错位、分享状态、通用标识及画像失败矩阵。
- **静态 Prompt 契约（7 项）**：检查空输入/无步骤、多目标、高风险、纯情绪、降级、伪实验禁止清单等文字契约是否存在；关键词存在不证明真实 Agent 会遵守。

R01 比较 `word200.json` 与 `word200-alt.json` 两份完整条件和结果，不再硬编码差异列表。H03 使用独立条件式 fixture，保留拒答、未知、条件式 v1 和至多 3 条分支。脚本通过仍不证明来源真实、改造合理或实践有效。

## 数据安全回归

画像用例实际执行：未确认拒写、确认更新、单备份恢复、删除、会话降级；另验证无效 upsert/delete 前后文件字节不变、合法 upsert/delete 两阶段写失败按原始字节回滚，以及 restore 备份阶段写失败后主文件和备份均回滚。临时事务副本在成功或完整回滚后删除；回滚也失败时保留并报告路径。

## 手动评测

`manual-runs.md` 含 3 个学习和 1 个居家纯 Prompt 端到端记录。按 1–5 分人工评：拆解准确、改造具体、执行可执行、未知诚实、问题价值、可读性、诚实边界。目标平均≥4且无单项≤2；自评分不能替代独立评审。

真实 Agent 多轮抽样见 `manual-runs.md`：职场复盘、摄影、团队例会三个独立子 Agent 均完成提问后生成。文本方案人工语义通过；团队实例首次 JSON 把 `name` 写成 `phase`，已作为真实失败记录。该抽样不是市场 UI 测试，也不代表所有模型。评审重点是高风险退出、问题价值、通用标识、条件式、来源链和同轮变量冻结。

## 运行命令

```powershell
python evals/run_evals.py
python scripts/validate_output.py evals/fixtures/word200.json
python scripts/validate_plan.py evals/fixtures/word200.json
```

失败用例的 PASS 表示校验器按预期拒绝无效数据，不是无效产物通过。没有真实执行记录时只能标待验证；模拟回答不能写成真实用户反馈。
